## What the end-to-end dry run found

The demo dry run and the final review found four "wired in tests only" gaps. Unit tests with fakes had hidden all four:

1. **T-606 (#96):** the API had no Service Bus producer, so every backtest and admin tiering submission returned 503,
   Azure included.
2. **T-607 (#98):** there was no SQL job store and the result aggregator never ran.
3. **T-607 (#98):** Azurite had no `backtests` container.
4. **T-608 (#100):** the dev Terraform never passed the auth, cursor and telemetry settings to the apps.

After the fixes, the same backtest request with the same seed gives an identical `result_sha256`.

## Follow-ups (not gate items)

- Nightly read-only drift plan on the SQL firewall rules (T-610 review S2; closes the fail-open window in R-25).
- **Aggregator resilience (T-607 S1):** a SQL outage abandons results with no backoff, so they can be dead-lettered
  after 5 deliveries.
- **Other job-store items:**
  - the shutdown race on the sync receiver (S3);
  - NVARCHAR binds against CHAR columns, which force a scan (S4);
  - the engine is not disposed;
  - no index on `principal_oid_hash`.
- **R-5:** the `Idempotency-Key` ADR for `POST /v1/backtests`.
- **R-28:** sign results, or verify `result_sha256` against the blob on read.
- **Cursor key rotation:** IaC does not create `cursor-hmac-key-previous`, so a rotation breaks in-flight cursors once.
- **Admin storage stats:** `/v1/admin/storage/stats` has no stats source and returns 503.
- **Ingest freshness alert:** ingest does not call `configure_telemetry` / `record_rows_written`, so the alert stays
  off.
- **Missing commands:** there is no DLQ discard command and no EIA/FRED ingest CLI. The latter is by design under
  ADR-0013.
- **Module layering:** move `serialise` and `MessageTooLarge` from `tidal.worker` to `tidal.contracts`.

  - 5 public methods without docstrings;
