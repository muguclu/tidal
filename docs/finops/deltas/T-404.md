Changed by the flag in existing modules: storage, Key Vault and SQL close their public endpoints (existing handling, verified
below); AKS nodes move into `snet-aks`; the Container Apps environment moves into `snet-aca` with an internal load balancer;
App Service gets VNet integration in `snet-app`; the legacy VM moves into `snet-vm` with default outbound access off.

## Decisions

| Choice | Why | Lever |
|---|---|---|
| snet-vm outbound = one Standard static public IP on the VM NIC | the exporter needs HTTPS out to `management.azure.com` (self-deallocate), Entra, PyPI and apt; a NAT gateway costs 8x more (table) for a VM whose compute is 0.05/month. The IP accepts no inbound traffic: Standard SKU is closed by default and the NIC NSG denies all inbound. | `network_vm_outbound = "nat_gateway"` keeps the VM address-less |
| Blob service endpoint on snet-vm anyway | free; satisfies the T-310 follow-up. It is redundant: the Blob private endpoint serves the exporter, and a service endpoint cannot reach a storage account with public access disabled. | none needed |
| Service Bus stays public | private endpoint needs Premium (ADR-0006) | unchanged |
| `snet-aca` is a /23 | the environment is Consumption-only; workload profiles would need only a /27 but the SKU/profile change is not part of this task | |
| App Service (B1) stays public | it is the API front door (Entra JWT); a private endpoint on the web app would block the GitHub-hosted deploy smoke test and every client outside the VNet | follow-up if the API should be private |
