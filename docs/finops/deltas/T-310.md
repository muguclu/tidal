# Cost delta T-310 (vm_legacy module, exporter, Logic App start)

Status: MODELLED from `docs/finops/prices.yaml` (westeurope, EUR) by `docs/finops/deltas/T-310_model.py`
(`python -I docs/finops/deltas/T-310_model.py`). Every figure below is that script's output; no number is typed in.
The allocated time per run (10 min) is an assumption until the first Cost Management export shows the VM meter.

Resources: `azurerm_linux_virtual_machine` (Standard_B1s, Ubuntu 24.04, StandardSSD_LRS OS disk), NIC, NSG (deny all inbound),
private VNet/subnet (/28), `azurerm_dev_test_global_vm_shutdown_schedule` (20:00 W. Europe), `azurerm_logic_app_workflow`
(Consumption, recurrence 21:55 + one built-in HTTP action), two VM-scoped custom roles with one action each, role
assignments (free). No public IP, no data disk, no Log Analytics agent.

## SKU justification and levers

| Choice | Why | Lever |
|---|---|---|
| Standard_B1s | SPEC-07 section 2; a few minutes of Python per day | `vm_size` (validated to B1s, B1ms, B2s) |
| StandardSSD_LRS, 30 GiB image = E4 | the cheapest managed SSD that holds the Ubuntu image (Standard HDD has no meter in prices.yaml and is slower to boot for a VM that boots daily) | `os_disk_type` |
| Deallocate after each run | compute is billed only while allocated; the disk is the only idle meter | exporter self-deallocate, 20:00 auto-shutdown as net |
| Logic App Consumption, built-in HTTP action | about 30 actions/month, inside the free 4,000 built-in actions | `start_enabled = false` pauses it |
| Default outbound access, no public IP | the VM needs HTTPS out (Blob, ARM, PyPI, apt); a Standard public IP adds the amount in the variants table, a NAT gateway more (UNPRICED, no meter fetched) | `subnet_id` to move into `snet-vm` (T-404) |
| No log shipping | journald on the VM; the Azure Monitor Agent plus a DCR would add a workspace ingestion meter and an extension; the 0.2 GB/day workspace cap would bound it but the value is low for a 3 minute job | follow-up if wanted |

No deviation from SPEC-07 section 2 SKUs.

## Notes

- Priced delta: **+2.16 EUR/month** scheduled, inside the cost-model rows "VM legacy" (2-4 active, ~1 parked) and "Logic App (VM start)" (< 0.1). Parked it is 2.11 with the VM kept deallocated, which is above the cost-model parked figure of ~1: the E4 disk is 2.11, not ~1. The orchestrator should change the parked column of the "VM legacy" row to ~2 (or 0 when `enable_legacy_vm = false`), and the active column to ~2.2.
- Outbound: `default_outbound_access_enabled = true` is kept explicitly on the subnet. Removing it breaks both the export (Blob) and the self-deallocate (management.azure.com), and the VM would then run until the 20:00 auto-shutdown (the 24/7 variant above). T-404 follow-up (noted in TASKS): Blob service endpoint plus NAT or an explicit IP.
- The exporter retries the token and deallocate for about 5 minutes on first boot (role propagation), within `TimeoutStartSec=15min`; a failed export or invalid config still deallocates, so a bad run costs minutes, not the 24/7 variant.
- UNPRICED: outbound data transfer (KiB to MiB, within the free 100 GB allowance), boot diagnostics managed storage, built-in Logic App actions above the free tier (API rounds the price to 0.0; not reached), NAT gateway (alternative, no meter).
- SPEC-06 section 2 gap: the `id-legacy-vm` row lists Blob Data Contributor on `exports` and `db_datareader`, but the exporter reads the cold Parquet, which needs **Storage Blob Data Reader on the `marketdata` container**. It is assigned (`legacy_vm_marketdata_reader` in `envs/dev/vm.tf`) and the SPEC-06 section 2 now has that cell. The `db_datareader` grant is NOT used: the feed is built from Parquet only, so the identity has no SQL access (least privilege).
- The exports path inside the container (`risk-feed/daily_bars_<date>.csv`) is not defined by the storage-layout contract (only the container and its 14 day lifecycle are). Add a line to the contract if a downstream consumer depends on it.
