| Item | Unit price | Monthly |

Fixed cost accrues daily while the registry exists, regardless of use or parking: the only lever is destroying the
registry. This is consistent with the cost-model.md row "ACR | Basic | ~5 | ~5" (modelled 4.40 to 4.54).

## Purge task

ACR Tasks bill compute time of each run (per-second task meter) and are not in `prices.yaml`, so no EUR figure is
stated. The task runs once a week, only deletes manifests via the registry API and finishes in seconds; it is
expected to be negligible. Action for the finops-analyst (T-501 meter list): add the "Task Duration" meter
and confirm from the first Cost Management read. Included build time is not assumed.

## Why Basic, why the purge matters

- Basic is the cheapest SKU (SPEC-07 section 2). Premium-only features (retention policy, geo-replication, private endpoint,
  content trust, quarantine, CMK, dedicated data endpoints) are not used; the weekly `acr purge` task replaces the
  Premium retention policy.
- Purge keeps stored GB under the 10 GiB included in the unit, so storage stays at 0 EUR. Without purge, CI pushes
  one `sha-*` image per merge and untagged manifests accumulate; each GB above the allowance costs 0.088 EUR/month.

## C9 before/after method (SPEC-09)

Metric: GB stored (ACR usage). Procedure:

1. Before: `az acr show-usage -n <registry> --query "value[?name=='Size'].currentValue"` (bytes) immediately before the
   Sunday 03:00 UTC run (or trigger it manually with `az acr task run -n weekly-purge -r <registry>` after pushing
   the build backlog), and record the manifest count by `az acr manifest list-metadata`.
2. After: same command after the run completes (`az acr task list-runs`).
3. Report GB before, GB after, and EUR = max(0, GB - 10) x 0.088 per month for both, with the date and the image
   push count in `docs/finops/results/`.

Retention knobs (variables): `untagged_retention_days` (default 7), `sha_tag_retention_days` (default 30), `purge_schedule`
(default `0 3 * * 0`, UTC). `v*` release tags and non-`sha-*` tags are never purged.
