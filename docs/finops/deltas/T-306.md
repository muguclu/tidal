Status: MODELLED from `docs/finops/prices.yaml` (westeurope, EUR) by `docs/finops/deltas/T-306_model.py`
(`python -I docs/finops/deltas/T-306_model.py`). Every figure below is that script's output; no number is typed in.

Resources: `azurerm_kubernetes_cluster` (Free tier, system pool 1x `Standard_B2s`), `azurerm_kubernetes_cluster_node_pool`
`spot` (`Standard_D4as_v5`, Spot, 0..10, 32 GB managed OS disk). The AKS-managed standard load balancer and public IP are
created in the `MC_*` node resource group. KEDA, workload identity, the OIDC issuer, Secrets Store CSI and the cilium
data plane have no charge.

## SKU justification and levers

| Choice | Why | Lever |
|---|---|---|
| Free tier control plane | no SLA needed for a dev portfolio cluster (SPEC-07 section 2) | tier |
| 1x B2s system node, `only_critical_addons_enabled` | smallest burstable node that runs the add-ons (KEDA, CoreDNS, CSI, cilium); user pods go to the spot pool | `az aks stop` |
| D4as_v5 spot, min 0 / max 10, `spot_max_price = -1`, eviction Delete | the list spot price is a fraction of on-demand; evicted jobs are redelivered by Service Bus | scale to zero + KEDA |
| 32 GB managed OS disk (P4) on spot nodes | Dasv5 has no cache or temp disk, so ephemeral OS disks are unsupported; the smallest size above the AKS minimum, billed only while the node exists | disk |
| Container insights off | would consume the 0.2 GB/day Log Analytics cap (cost-model: 2.63 EUR/month ceiling) | opt-in variable |

## Findings for the cost-model fold (orchestrator)

- The fixed network lines are larger than the current cost-model row "AKS disks / LB / public IP: 3-6 active, 1-4 parked".
  With the prices.yaml meters the standard LB plus public IP alone are the "LB" and "Public IP" rows above, and a stopped
  cluster still pays the OS disk, LB and IP if they are retained (UNVERIFIED: Azure may release them on `az aks stop`;
  measure in the first park test, then update `park` cost). Proposed cost-model row values: active = the fixed subtotal
  minus the B2s line, parked = the parked subtotal, or 5.11 (disk only) if the first stop shows LB and IP are released.
- The system pool row "10-35 (35 if never stopped)" matches the B2s line.
- The spot row "1-5" matches the light scenario; the heavy scenario (spot total in the table above, with OS disks) is slightly above the upper bound.
- The `terraform destroy` at the end of the cloud window (LOCAL-DEV section 2) is the real cost control for the parked
  figures: parked is only for pauses inside the window.
- Quota: 10 spot nodes need 40 vCPU of Standard Dasv5 spot quota. New pay-as-you-go subscriptions often start lower;
  set `aks_spot_max_count` accordingly.
